# J5 A2A runtime configuration

`envelopes.v1.json` is the human-owned wording source for every injected A2A envelope and the MCP tool descriptions. Templates use literal `{{name}}` placeholders; `EnvelopeFormatter.ts` is the only renderer. Change wording in the JSON file, keep every referenced placeholder, and bump `version` when the rendered contract changes.

`delivery-config.v1.json` owns the retry backoff and alarm threshold. Attempts reuse one upstream command/message id pair derived from the durable ledger message id. Increasing an attempt never rotates those ids: a permanently rejected upstream receipt must become a visible alarm rather than risk a second injection.

`ThreadRegistration.ts` is the one place a thread becomes a participant. A thread's home is its project, which upstream fixes when it creates the thread, so registration takes only the thread id. `LifecycleService.ts` calls it for every stored `thread.created` event and, at start, for every existing thread that is not registered yet; the services that act for a caller call it lazily. A Subagent-lineage thread, a deleted thread, or one this server does not have is never registered. Beneath it, `HomeRegistrar.ts` records one immutable `participant.joined`, replays the same registration without another event, and rejects a different project. `getHomeForThread` reads historical join events so later lifecycle retirement cannot erase or reassign a thread's home. Neither is an agent tool.

Placement and provenance are an agent-only organization overlay. Creation records immutable typed provenance (`spawned-by`, `forked-from`, or `unknown`) and derives the initial placement from that fact. Humans and person ids are never placement-tree nodes. There is no reparent command; the retained R21 human-only reparent law lives in the A6 ticket record. Crews retire only as a unit: archiving a Captain's thread retires its live Crews through `CrewCaptainArchiveCascade.ts`, and `crewSeatArchiveGuard.ts` refuses archiving or deleting a seat on its own.

Human-inbox routes currently authenticate the environment scope, not the named person. The caller supplies the `human:<person-id>` used for reads and attributed answers; person-bound authentication remains deferred to X4's peer registry. Until that identity seam lands, an `orchestration:read` session can read any known person's inbox and an `orchestration:operate` session can answer as any known person.

The first J5 runtime start mints one opaque, durable `human:<person-id>` local-operator record in the host registry. A person is host-global addressability state: minting creates no home or membership event. The participant union remains broad enough to read historical human membership facts, while the live membership projection is agent-only; participant directories synthesize registered people alongside member agents.

For a send between projects on one server, the receiver ledger's idempotent `message.received` records durable acceptance of the sender's act before transport is attempted. It does not claim successful thread injection: delivery success, retries, and the terminal alarm remain in the sender project's delivery projection. Across servers the receiving peer writes that `message.received` row and its acknowledgement is the sender's delivery receipt: the receipt means the peer accepted the message, and injection into the thread is the peer's own pending delivery, which retries and alarms in the peer's projection, attributed to the sender.

Byte-equivalent rebuilds for the A2 exchange and delivery projections are deferred to the measured-projections milestone (M5). A2 keeps those tables derivable from the communication ledger but does not expose their rebuild operation.

A3 requires every sent-message event and delivery row to declare an explicit envelope channel. Peer sends write `peer`; silence notices write `silence_notice`, reuse A2's versioned silence-notice formatter, and bypass peer/human wrapping in the shared transport.

The silence detector checkpoints its global v2 event sequence in the J5 migration lane. A new installation first reconciles only open delivered exchanges against current thread projections, records the existing v2 high-water mark, and then tails from that durable cursor; retries replay at most the uncheckpointed tail instead of scanning the event store from genesis on every boot. A broken v2 subscription uses capped exponential backoff without re-running the reconciliation scan on every attempt.

Archive closure is a separate platform lifecycle write authority in `LifecycleService.ts`; it is never an A3 silence action and is not exposed through the agent MCP toolkit. Participant archive appends `participant.archived`, retaining identity, immutable home, and provenance while disabling addressability. It terminates affected open Exchanges with `exchange.dropped` and stable system notices, and cancels pending deliveries. Accepted queue entries are withdrawn before recording cancellation, including outgoing work queued in another thread. A delivery that already reached a run or a successful provider steer remains delivered; this records delivery, not processing completion. Thread archive, including `t3_thread_organize`, can leave an active run executing; `j5_stop_agent` remains the explicit interruption tool. Human notices require a durable terminal inbox row. `j5_list_participants` hides archived agents unless `include_archived` is true; those rows explicitly remain unaddressable.

The lifecycle reactor consumes committed archive, unarchive, and delete events from a durable cursor. Unarchive restores the same membership without reopening Exchanges, replaying cancelled messages, or starting a turn. Delete removes membership and live placement while retaining peer history and provenance events; surviving children display as roots when their placement parent is absent. Historical `participant.left` facts remain permanently retired, including after migration, membership rebuild, or thread unarchive. Threads that are not participants (provider Subagents) remain no-ops.

`ArchiveFactsService.ts` is the read-only boundary behind the human pre-archive warning. It reports open exchanges in both directions without deciding archive or settle policy. Placement comes from `placementFactsLayer`, which `runtimeLayer.ts` supplies; a placement read that fails is reported as `unknown`, and a checked empty subtree is a different `none` state. `preArchiveFactsRead.ts` adds the thread's Crew relations, and `ClientReadsService` serves the read as the RPC `j5.archive.readFacts`. It is not an agent tool, because an agent is the wrong consumer for a human archive dialog.

The J5 `t3_thread_organize` handler keeps upstream's same-project rule and adds only the Crew-seat archive guard. The shared lifecycle reactor handles closure for every command door. Human archive warnings continue to use `ArchiveFactsService`; the retired `archive_agent` confirmation service is removed.

Machine participants (`MachineParticipantService.ts`, `RosterService.ts`, `MachineSenderHttp.ts`, and the `j5 a2a` CLI in `../cli/a2a.ts`) are registered non-agent senders in one project, which never changes, and with no thread. Their `participant.joined` event projects into `j5_a2a_machine_participant`, never into the agent-only membership table, and they have no lifecycle events yet. `SendService.sendAsMachine` resolves the sender from that table and then shares `sendInternal` with the agent path, so a machine send commits the same `message.sent` event under the same command-id replay rules; a machine id as receiver is refused, and the `peer` channel renders a machine sender with the `machineMessage` template. The HTTP surface authorizes on the `a2a:send` scope plus a session subject naming a registered machine; identity is never a request field, and the send command id is derived from the subject and the client request id.

Outside agents (`mcp/outsideAgent.ts`) are MCP clients signed in through upstream's OAuth flow: `scope.client` with no `scope.thread`. Each is the participant `outside:<session id>`, with no `participant.joined` event and no membership, so `j5_a2a_outside_agent` is the only record of one. Declare a tool that needs a calling thread with `actsAsThreadCaller` or `readsAsThreadCaller`, never with `McpToolAccess` directly: `writes` and `reads` admit an outside agent. The approved level is checked in the handler when a call is made, not at delivery.
